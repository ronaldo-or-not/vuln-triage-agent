# 4주차 (2): 진단 보고서 문서 처리

## 질문

진단 보고서(PDF, 스캔 PDF, DOCX, XLSX)를 받아 "어떤 패키지 몇 버전에 어떤 취약점이 있다"를 정확히 뽑고,
그 패키지를 트리아지 에이전트로 넘길 수 있나? **결정적 파싱과 LLM 중 무엇을 언제 써야 하나?**

## 평가 문서

- 2주차 실제 케이스 10개의 정답(실제 패키지·버전·CVE)을 양식 5가지로 만든 문서 50개 (`eval/docs/make_docs.py`)
- 내용은 실제, 양식은 합성이다. 공개된 실제 진단 보고서는 라이선스와 정답 확보가 어려웠다
- 일부러 넣은 난관: 여러 쪽에 걸친 표(이어지는 쪽에 머리글 없음), 패키지별 묶음 목록, 서술형 문장,
  기울임·잡음이 있는 스캔 이미지, 참고문헌·배경에만 나오는 무관한 CVE(뽑으면 오답)

| 양식 | 설명 |
|---|---|
| pdf_table | (패키지, 취약점)마다 한 행, 큰 케이스는 2쪽 |
| pdf_grouped | 패키지 제목 아래 목록 + 참고문헌에 무관한 CVE |
| pdf_scan | pdf_table을 110dpi 이미지로, 기울임·잡음·JPEG 압축. 텍스트 층 없음 |
| docx_prose | 모의해킹 보고서식 서술 + 배경 문단에 무관한 CVE |
| xlsx | 다른 열 이름, 한 칸에 ID 여러 개, 메모 시트에 무관한 CVE |

## 결과 (문서 50개, (패키지, ID) 쌍 기준 micro 평균)

| 방법 | pdf_table | pdf_grouped | pdf_scan | docx_prose | xlsx | 전체 재현율 | 정밀도 | 무관 CVE 오추출 | 문서당 비용 | 문서당 시간 |
|---|---|---|---|---|---|---|---|---|---|---|
| 결정적 (PyMuPDF 1.28) | 0.995 | 1.000 | **0.000** | 1.000 | 1.000 | 0.799 | 1.000 | 0 | $0 | 0.4s |
| **Haiku 5.5** | 1.000 | 1.000 | **1.000** | 1.000 | 1.000 | **1.000** | 1.000 | 0 | $0.0005 | 3.1s |

Haiku 5.5는 50개 전부 완전 일치했다. 50개 전체 비용은 $0.025다. 스캔 문서도 2쪽짜리 50행 표까지 모두 맞췄다.

## 발견

1. **스캔 문서는 결정적 방식으로 못 읽는다.** 텍스트 층이 없어서 OCR이 필요하다. Haiku는 페이지 이미지를
   직접 읽어 10/10을 맞췄다. 비용은 문서당 $0.0006이다.
2. **결정적 방식은 쪽 경계에서 행 하나를 놓쳤다** (struts 표 2쪽 경계의 `CVE-2021-31805`). 쪽마다 표를 따로
   인식하기 때문이다. 이런 문제는 문서를 직접 보기 전에는 예상하기 어렵다.
3. **결정적 파이프라인은 라이브러리 버전에 조용히 깨진다.** 서버(PyMuPDF 2.1)에서는 표 칸의 문장부호 순서가
   뒤섞여(`CVE-2017-5645` → `CVE20175645\n- -`) pdf_table이 **0점**이 됐다. 같은 코드가 로컬(1.28)에서는
   0.995였다.
   - 오류도 경고도 없이 결과만 비었다.
   - 칸 텍스트를 좌표 영역으로 직접 읽게 바꿔 두 버전 모두에서 동작하게 했다 (서버 재평가: 0 → 0.995, 로컬과 동일).
   - 같은 회귀를 잡는 테스트를 추가했다 (`test_pdf_table_ids_with_hyphens_survive_extraction`).
4. **결정적 추출기의 만점은 과대평가다.** 이 문서들의 양식을 알고 짠 코드라서, 처음 보는 실제 보고서 양식에서는
   이만큼 나오지 않을 것이다. Haiku는 양식별 코드가 없어서 일반화 능력을 더 공정하게 보여준다.

## 설계 결론

- 기본은 **LLM 추출**(Haiku 5.5): 양식에 상관없이 동작하고, 스캔까지 읽으며, 비용은 문서당 0.1센트 미만이다
- 결정적 추출은 **무료·즉시** 경로로 남긴다. 구조가 정해진 사내 양식이나 대량 일괄 처리에 쓴다
- 어느 방식이든 보고서에 적힌 CVE 목록은 그대로 믿지 않는다. 패키지·버전만 트리아지로 넘겨 1주차 도구로 다시
  확인한다 (`vulnagent extract --triage`). 보고서가 오래됐거나 틀렸어도 결과는 현재 데이터 기준이 된다

## 한계와 다음

- 양식이 합성이라 실제 스캐너 출력(HTML/JSON/SARIF, 벤더 PDF)의 다양성을 다 담지 못한다. 실제 보고서 몇 개를
  확보해 같은 평가에 추가하는 것이 다음 단계다
- 손상이 더 심한 스캔(저해상도, 손글씨 메모, 표 일부 가림)은 아직 넣지 않았다
- PPTX와 이미지 파일(PNG) 입력은 아직 지원하지 않는다 (PDF 페이지 이미지와 같은 방식으로 붙일 수 있다)
